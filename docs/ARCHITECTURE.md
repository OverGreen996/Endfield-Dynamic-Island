# 架構

靈動島 Avalonia → 程式內 NativeAssistantService → 一次 AI 理解（Gemini → Groq → Cloudflare） → NativeSearch → Exa / Tavily / Firecrawl → 公開正文 → 同順序 AI 整理。
一般文字聊天：Gemini／Groq 由理解與記憶判斷、專門答覆兩次生成完成；CF 同一次生成完成理解、記憶判斷與答覆。必要澄清只用理解階段的一次生成。需要外部資料才插入搜尋，整理階段同時完成措辭，不再加第三次潤稿。音樂、HUD、提醒與本機記憶維持原責任，不參與搜尋輪替。

## v0.28.14 圖片對話

OCR 只負責本機讀字，已設定 AI 時，圖片文字連同上下文進入既有理解／答覆路徑。只貼圖額外提供最近一輪的資料節錄（每則最多 700 字），幫助模型承接話題；原有上下文不縮短。圖片提示僅影響圖片這一輪，搜尋與私人動作驗證不採口令規則。

## v0.28.13 共用對話表達

NativePrompts.Conversation 是三家模型共用的核心回應原則；VoiceExamples 只供專門普通答覆和 CF 合併答覆使用，不增加 Gemini／Groq 理解階段負擔。原搜尋整理與數量定義保持獨立。一般 Gemini／Groq 正式回答同時讀取原問題、上下文與理解階段草稿；草稿放在標為非新使用者資訊的 JSON 中，不重新寫入記憶，也不是可靠外部事實來源。

ConversationReply 的一次重寫涵蓋末尾多餘問句與狹窄匹配的客服邀請，不按這些詞決定搜尋、記憶或操作，也不每輪添加潤稿。引述詞句的一般解釋不觸發邀請檢查。必要 clarify 直接回覆，不進重寫；搜尋答覆也不套普通聊天的邀請檢查。Groq 的 schema 只由 response_format 提供，繼續 strict=true 與本機 schema 驗證。

## v0.28.12 CF 合併答覆

當理解階段實際使用 Cloudflare 且 action=answer，直接將已驗證的 plan.Answer 交給既有對話輸出檢查，不再呼叫專門 writer。CF 理解 schema 追加 CombinedReply，要求 answer 作為最後答覆，memory／operations 維持原契約。選取後上下文、人格快照、原文驗證、取消及待提交操作遮罩仍沿用。必要澄清不重寫；多餘收尾追問最多一次重寫，使用 answer-only schema。CF 搜尋、Gemini、Groq 均保留兩步流程。沒有固定加速比例的承諾，CF 的服務端延遲與 30 秒單次逾時仍存在。

已判定 answer 的普通對話若仍追加末尾問句，最多再重寫一次；不重做理解、搜尋或記憶。重寫仍保留多餘問句時只保留前面已答覆的句子，空答覆拒絕成功。clarify 的必要問題不經此檢查；程式碼顯示沿用原路徑；圖片改走本機 OCR。

## v0.28.11 專門答覆

理解階段保留 AI 搜尋、記憶與操作判斷；answer 路線不再直接顯示分類草稿，而是以原使用者訊息和同一上下文呼叫專門的 Reply 指令。搜尋整理與一般答覆只接受 answer 欄位，無法覆蓋理解階段的記憶或產生額外操作。同輪延續已選模型與人格快照，輪替機制不变。人格先提供，當輪任務規則最後套用，避免習慣性的角色問候掩蓋當輪要求。備援 schema 的中文描述保持可讀，減少內嵌 Unicode 轉義。

理解、記憶／人格、整理答覆是三個職責，普通回合只有兩次生成：新記憶在理解时一併判斷，既有人格和記憶直接讀取本機資料。Gemini 理解＋Groq 答覆已用真實 API 比較速度與品質；品質收益未達門檻，目前沒有分工模式選項。一般回合仍優先同一 Gemini 組完成，受限才照原順序備援，沒有每輪同時呼叫三家模型。

Cloudflare 使用 Qwen3.8-27B 的 instruct 模式及嚴格 JSON schema，專門聊天答覆上限 2048 tokens，其餘 4096；單次逾時 30 秒。這是最後文字備援，延遲及免費計算額度消耗仍較主力高，無新 API 憑證或執行環境。

WindowsLocalOcr 使用 Windows.Media.Ocr 和系統已安裝的語言（繁中優先），由主程式內直接辨識 PNG；沒有 NPU、新模型下載、OCR 背景程序或額外 API。取消與 15 秒逾時、圖片／文字大小限制、空白與未安裝語言有明確結果。已設定 AI 時，無附帶問題也使用既有文字路由，將 OCR JSON 與上下文交給模型決定回應、搜尋或釐清；無 AI 設定或只搜尋模式無附帶問題才回覆本機文字。生成用的圖片任務提示與原始 caption 分開，ParsePlan 仍核對原始 caption，空 caption 不提供任何個人操作依據。ParsePlan 的記憶／操作來源仍只核對原使用者文字，不包含 OCR 文字。只搜尋模式可利用 OCR 字詞，不需圖片模型。外觀、頭像與 HUD 沿用。

## v0.28.6 AI 意圖與個人記憶

- 聊天入口不再執行口令解析、句型分類或關鍵字搜尋路由。AI 一次理解後回傳獨立的 action、memory 與 operations 陣列。
- 記憶提議帶有本次原文、簡潔中文事實、AI 產生的中文分類、持續性判斷及可選既有編號。分類不再使用固定清單；本機僅驗證格式、來源與加密儲存。
- 操作支援單次提醒、列表及刪除；AI 解析台灣時間，本機驗證日期/識別碼並實際排程。無特定口令要求，不確定則由 AI 釐清。
- 搜尋前的個人判斷可與搜尋共存；證據整理不重新提取記憶或本機操作。搜尋/整理失敗仍保留已完成的個人判斷。取消回覆不提交新事項。
- API 已確認拒絕的 400 不等於用量不明，保留請求計數但釋放 token 預留；既有同類誤鎖可恢復。其他不明用量仍受保護。
## v0.28.0 原生執行環境

- AI、金鑰設定、用量與搜尋在主程式內執行，不使用 Node、本機監聽埠或 PowerShell 啟動工具。
- 安裝包含 .NET runtime。帳本使用 Windows `winsqlite3.dll`，加密使用 CurrentUser DPAPI，不需另裝資料庫。
- NativeConfiguration 相容既有政策、綁定指紋與加密金鑰；GeminiLedger 相容舊 SQLite 帳本。升級不重设計數、鎖或額度。
- CountTokens 成功且原子保留用量後才能 GenerateContent；取消或不明用量保持保護鎖，已收到 500/503 使用短期冷卻。
- NativeSearch 在發送前保留每家用量。Exa、Tavily 移除本機用量上限；任何 API 搜尋失敗寫入持久封鎖，下個月 2 號台灣時間 00:05 到期，下一次搜尋重試，重試失敗再次延至下月 2 號。使用者取消不封鎖，近期備援快取不延後到期重試。Tavily 搜尋不先查用量；手動查詢官方餘額僅更新參考數值，不解除或延長搜尋封鎖。Firecrawl 也無本機點數上限，以 `/v2/team/credit-usage` 官方剩餘點數為準。手動設定 `billingDay` 及 `billingMinute`（台灣時間），不足時等至最近的設定日期；到期再核對，仍不足則隔一小時重查。官方期間欄位供用量紀錄參考，不覆蓋手動切換日。技術錯誤使用短期冷卻，金鑰錯誤需修正金鑰。
- 公開正文讀取只接受公網位址，DNS 結果檢查後固定連線 IP，重新檢查轉址，限制時間與大小。
- 搜尋設定使用原生 Avalonia 視窗；金鑰不進入瀏覽器、不印至紀錄、不配送。
- Daily Agent 保有自己的金鑰、帳本、快取及輪替，不使用靈動島的資料或模組。

文件中的 `ChatGPT/GeminiHub` 現為相容資料位置，已不代表背景服務。舊服務程式、啟動腳本與下載工具已移除；僅保留一次性舊程序遷移保護。

音樂播放仍由独立的 .NET MusicPlayerHost 執行，沿用主程式已安裝的 runtime；YouTube 使用 Windows WebView2。HUD、通知、提醒和記憶不等待模型或搜尋啟動。

## v0250 顯示與採樣分離

硬體方案隱藏時約每五秒預採樣，顯示時每秒更新；喚出直接讀快取。設定預覽與 HUD 共用同一個採樣服務。隱藏預採樣不啟動 HTTP 或 ping 探測。

## v0.28.7 對話與模型輪替

DialogueInstructions 將理解階段與回答階段分開；一次理解同時產生自然回覆及可選的記憶/操作。搜尋整理只回答問題，不再分類記憶。舊歷史只用於承接，介面不呈現來源清單或報告模板。

NativeBackupModels 直接呼叫 Groq GPT-OSS 120B 與 Cloudflare Qwen3-30B-A3B，使用結構化輸出及本機格式驗證。Gemini 在正式執行模式不再套用舊本機次數/token 上限；保留歷史帳本與計數，只以官方錯誤建立冷卻。Gemini 日額度按太平洋午夜，Cloudflare 按 UTC 午夜，Groq 按回應資訊；重試只在下一次需求發生。

NativeSearch 的 `rotationMode` 預設為 `priority`；`per-turn` 在每次成功搜尋後切至自訂順序的下一家。輪替游標存於既有 SQLite 的獨立 `rotation` 表，與快取提交同一交易；設定草稿不含游標，因此一般儲存不會倒退。每輪對話最多呼叫一次 SearchAsync。純聊天、快取、取消或全數失敗不更新游標，既有可用性/官方餘額/封鎖仍逐家檢查。

## v0.28.8 人格與 Gemini 主力池

- AssistantPersonaStore 加密管理不可變的角色人格／互動規則，NativeAssistantService 在每轮開始捕獲一次快照；中途切換不改變已開始的回覆。Persona 僅影響自然語氣，結構化操作與記憶原文校驗保持原優先權。
- NativeGeminiPool 依序选择 1–5 的可用組，保留同輪已成功的組做搜尋整理；Gemini 全部暫不可用才進入既有 Groq → Cloudflare 文字備援。只搜尋、取消與設定不額外呼叫模型。無新服務或執行環境依賴。
- 第 1 組保留 NativeConfiguration 與既有 GeminiLedger；額外金鑰採 Windows DPAPI，帳本依金鑰指紋獨立且跨槽位保留。儲存不清除用量或冷卻，重啟按恢復狀態接續。Runtime status 僅輸出數量、用量與狀態，不輸出人格內容或金鑰。
